## Project: NFL Draft Boom/Bust Model (`nfl-draft-model`)

### 2026 Retrospective
*To be filled in after April 24 draft — did the model's calls hold up?*

**What we proved:**
- A 15-feature XGBoost model trained on 3,750 historical prospects can generate
  credible, position-specific boom/bust probabilities from pre-draft data alone
- Program pipeline features (10-year rolling window by position group) are novel
  and computationally defensible — most public models treat college program as flat categorical
- CB and S warrant separate sub-models — outcome profiles are meaningfully different
  (~4% vs ~12% boom rate) and combining them masked signal
- TabPFN (zero-shot foundation model) lost to tuned XGBoost on all 8 position groups —
  interesting negative result, worth writing up
- RB evaluation from pre-draft data is essentially noise (RMSE ≈ null model) —
  the market prices RB athleticism efficiently enough that beating pick expectations
  is unpredictable from combine data alone

**What hurt:**
- Conference tier (`conf_tier`) was NA for all 2026 prospects — school→conference
  mapping was never built
- Draft age / underclassman flag was NA for most of the cycle — no birth date source wired in
  until draft eve; patched with a manual CSV from dynastyleaguefootball.com + establishtherun.com
- College name normalization (nflreadr "Ohio St." vs cfbfastR "Ohio State") caused
  silent join failures; fixed late in the cycle
- Non-combine prospects (Caleb Downs, Sonny Styles) were silently dropped until
  a mock-board backfill was added — a near-miss on two top-10 prospects

### Architecture Investments
*Each requires design thought before coding. Plan the approach first.*

#### TabPFN Combined-Position Run
- **Hypothesis:** TabPFN's in-context learning may scale better with ~3,400 rows
  (all positions combined) vs. per-group 300–600 rows. XGBoost is tuned for small-n;
  TabPFN may not be.
- **Approach:** Single model, all positions, same CV folds restructured cross-group.
  Use position-masking (NA) for inappropriate stats rather than dropping features.
  Compare RMSE against per-group TabPFN weighted average.
- **Content angle:** "Does a foundation model get smarter with more data?" — standalone
  Substack post either way.
- **Effort:** 1 session (infrastructure already exists)

#### FT-Transformer
- **Why not in 2026:** Genuine transformer architecture needs cross-group pretraining
  to work at this data size. That requires full offseason design — can't bolt it on.
- **Approach for 2027:** Pretrain on all positions combined (unsupervised, masked
  feature reconstruction), fine-tune per position group. Requires PyTorch directly,
  not tabnet/torch R packages.
- **Reference:** Gorishniy et al. (2021) "Revisiting Deep Learning Models for Tabular
  Data" — FT-Transformer is the architecture to beat on structured tabular data.
- **Effort:** 3–4 sessions; design doc first

#### Social Media Risk Signal
- **Hypothesis:** Prospects posting heavy physique/peak-condition content close to
  draft correlates with early-career injury risk. "Peak too early" signal.
- **Examples:** Saquon Barkley, Nick Chubb (injuries); Derrick Henry (outlier durability).
- **Sources:** Instagram and YouTube (public, accessible); avoid X ($100–500/month API).
- **Pipeline:** Image/video classification via LLM API → binary signal per prospect per week
- **Effort:** 2–3 sessions for a prototype; requires LLM image API budget
- **Do not build before 2027 draft**

#### Observable / D3 Interactive Embeds
- **What:** Interactive player cards and boom/bust scatter plots for Substack embeds.
  Readers filter by position, sort by p_boom, click a player to see SHAP waterfall.
- **Effort:** 2 sessions if using Observable Framework (lower JS overhead)
- **Dependency:** Stable CSV output format from `05` — lock the schema before building

#### OpenClaw Automation (Mac Mini M4)
- **Planned capabilities:** RSS monitoring → LLM summarization, X list monitoring →
  model-informed reaction drafts, scheduled data refresh
- **Status:** Mac Mini M4 on order. Design decisions for output flow (GitHub trigger vs.
  S3 vs. direct push) intentionally deferred — revisit when hardware arrives.
- **Do not build toward this in `nfl-draft-model` repo**

### 2027 Model Wishlist
*Features worth the investment if there's a full offseason to build them.*

- **Snap count / usage data** — college targets, routes run, snap%, opportunity share;
  better than raw counting stats for evaluation
- **Scouting report NLP** — PFF, The Draft Network write-ups as unstructured signal;
  LLM embeddings as features
- **Transfer portal tracking** — players who transferred have shorter histories at their
  final school; program pipeline features need transfer-aware lookups
- **Injury history** — college injury data is scattered but available; known pre-draft
  injury is signal the model currently ignores
- **Positional value weighting** — AV systematically undervalues OL and overvalues
  skill positions; a position-adjusted outcome might sharpen predictions
- **Draft capital model** — predict where a player *will* be drafted as a separate
  model; feed draft capital prediction into boom/bust model as a feature
